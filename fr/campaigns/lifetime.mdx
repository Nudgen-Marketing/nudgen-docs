## Ce que cette page vous aide à faire

Créer une campagne à vie qui reste prête pour les événements de votre système. Chaque déclencheur valide crée au plus une exécution et envoie un coup de pouce au contact dans sa charge utile.

## Pourquoi c'est important

Vous pouvez envoyer des e-mails pertinents en temps opportun sans créer et lancer de campagnes à plusieurs reprises. Votre backend contrôle le moment où un événement se produit, tandis que Nudgen conserve le contenu des e-mails, la livraison, le suivi et les préférences de contact en un seul endroit.

## Quand utiliser une campagne à vie

Utilisez une campagne à vie pour les e-mails basés sur des événements, tels que :

- Confirmations de commande
- Rappels de paiement
- Intégration basée sur des événements
- Mises à jour de compte ou d'abonnement

Contrairement aux campagnes ponctuelles et goutte à goutte, une campagne à vie ne ne pas envoyer immédiatement à une audience enregistrée. Son audience est toujours **Trigger**.

## Créer et activer une campagne

<Steps>
 <Step title="Create a Lifetime campaign">
 Accédez à **Campagnes**, cliquez sur **Nouvelle campagne**, puis choisissez **Durée de vie**. Ajoutez le nom de la campagne, l'objectif, la configuration de la marque et un lien CTA facultatif.
 </Step>
 <Step title="Define runtime parameters">
 Ajoutez chaque valeur que votre système fournira au moment de l'envoi. Un paramètre crée une variable `data.*` : par exemple, `order_id` devient `{{data.order_id}}` dans l'e-mail.
 </Step>
 <Step title="Create the email">
 Générez ou écrivez le sujet et le code HTML, puis ajoutez vos variables d'exécution à leur place. Prévisualisez l'e-mail et envoyez un test avant de l'activer.
 </Step>
 <Step title="Activate the campaign">
Enregistrez-le en tant que brouillon, puis cliquez sur **Activer**. Nudgen vérifie que les paramètres requis sont représentés dans l'e-mail et que le contrat de paramètres n'a pas changé depuis la génération.
 </Step>
 <Step title="Create a trigger key">
 Accédez à **Paramètres** → **Clés API** et créez une **Clé API de déclenchement d'équipe**. Stockez le secret `ndg_team_*` dans votre backend ou votre gestionnaire de secrets ; ne le placez jamais dans le code d'un navigateur ou d'une application mobile.
 </Step>
</Steps>

## Paramètres d'exécution et variables de modèle

Votre `variableManifest` est le contrat entre le modèle d'e-mail et l'objet `data` de chaque déclencheur. Une campagne peut définir jusqu'à 100 variables.

| Champ | Tapez | Obligatoire | Description |
| --- | --- | --- | --- |
| `path` | `data.<name>` | Oui | Chemin variable. Les chemins imbriqués tels que `data.order.total` sont pris en charge. |
| `type` | `string`, `number`, `boolean`, `date` ou `url` | Oui | Tapez le déclencheur que vous devez fournir. Un `date` doit être une chaîne de date valide et un `url` doit être HTTP(S). |
| `required` | booléen | Oui | Les valeurs manquantes renvoient `422` sauf si une valeur par défaut est définie. |
| `defaultValue` | chaîne, nombre ou booléen | Non | Valeur de secours qui doit correspondre au type de variable. |
| `description` | chaîne | Non | Expliquez la valeur afin que vous et Nudgen AI puissiez l'utiliser correctement. |

Par exemple, utilisez `{{data.order_id}}`, `{{data.total}}` et `{{data.order_url}}` dans un modèle. Vous pouvez également utiliser `contact.*`, `event.*`, `brand.*` et des variables héritées telles que `{{firstName}}` et `{{brandName}}`.

Nudgen échappe aux valeurs de variables insérées dans HTML. Les modèles ne prennent pas en charge JavaScript, les expressions ou les boucles. Toute variable utilisée dans un `href` doit être une variable `data.*` déclarée avec le type `url`.

## Gérer le cycle de vie

| Statut | Ce que cela signifie |
| --- | --- |
| **Brouillon** | Configurez la campagne et testez son email. |
| **Actif** | Nudgen accepte les déclencheurs authentifiés. |
| **En pause** | Nudgen n'accepte pas de nouveaux déclencheurs. Vous pouvez le reprendre. |
| **Archivé** | La campagne est définitivement fermée et ne peut plus être activée. |

Les transitions valides sont `draft → active → paused → active` et `active|paused → archived`.

<Note>
La pause ou l'archivage annule les exécutions qui sont toujours en attente ou en file d'attente. Une exécution en cours de traitement peut encore envoyer.
</Note>

Chaque exécution capture le contenu de la campagne et envoie les paramètres lorsque Nudgen reçoit le déclencheur. La modification d'une campagne active n'affecte que les déclencheurs ultérieurs, pas les exécutions qui existent déjà.

## Déclencheur depuis votre backend

Appelez le point de terminaison du déclencheur à partir d'un serveur de confiance après avoir validé l'événement source. Utilisez la clé API du déclencheur d'équipe, et non un jeton d'accès personnel (PAT).

```bash
curl -X POST "$NUDGEN_APP_URL/api/v1/campaigns/$CAMPAIGN_ID/triggers" \
  -H "Authorization: Bearer $NUDGEN_TEAM_API_KEY" \
  -H "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "eventId": "order_123",
  "eventName": "order.created",
  "occurredAt": "2026-08-23T10:00:00Z",
  "contact": {
    "email": "an@example.com",
    "externalId": "customer_456",
    "name": "An Nguyen",
    "metadata": { "company": "Nudgen" }
  },
  "data": {
    "order_id": "order_123",
    "total": 490000,
    "order_url": "https://example.com/orders/order_123"
  }
}
JSON
```

Conservez le même `eventId` lorsque vous réessayez un événement. Nudgen renvoie l'exécution existante avec `200` et `duplicate: true` au lieu d'envoyer un autre nudge. Une nouvelle exécution renvoie `201`.

## Intégrez en toute sécurité

- Déclenchez à partir d'un consommateur ou d'un backend de webhook et vérifiez le webhook entrant avant d'appeler Nudgen.
- Réessayez les erreurs réseau, `429` et `503` avec un intervalle exponentiel et le même `eventId`.
- N'enregistrez pas les en-têtes ou les charges utiles `Authorization` contenant des données de contact sensibles.
- Faites régulièrement pivoter les clés de déclenchement et révoquez immédiatement une clé si vous pensez qu'elle est exposée.
- Créez une campagne par type d'événement et contrat variable afin que les modèles et les audits d'exécution restent clairs.

## Surveillez les exécutions

Ouvrez la campagne dans le tableau de bord pour voir les exécutions récentes et leurs statuts. Une exécution peut être `pending`, `queued`, `processing`, `sent`, `skipped`, `cancelled`, `failed` ou `delivery_unknown`.

`skipped` signifie que le contact a été désabonné ou rebondi, donc Nudgen enregistre l'événement mais n'envoie ni ne consomme de quota. `delivery_unknown` signifie que le fournisseur a peut-être accepté l'e-mail mais que le résultat final de la livraison était incertain ; Nudgen ne réessaye pas automatiquement pour éviter un envoi en double.

Pour les requêtes de configuration, de déclenchement et d'exécution par programmation, consultez l'[API du développeur](/fr/agents/api).
