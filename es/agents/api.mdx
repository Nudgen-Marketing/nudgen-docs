## Descripción general

La API de desarrollador de Nudgen brinda scripts, herramientas internas y agentes de IA una interfaz REST predecible para su espacio de trabajo. Utilice un token de acceso personal (PAT) para administrar los recursos del espacio de trabajo. Utilice una clave API de activación de equipo solo para activar una campaña de por vida desde su backend.

## Por qué esto es importante

Puede automatizar los flujos de trabajo de marketing y retención basados en eventos sin compartir una sesión del panel. Las PAT mantienen la administración del espacio de trabajo revocable, mientras que una clave de activación de equipo estrecha permite que un servicio de producción envíe un empujón activado por evento sin acceso amplio al espacio de trabajo.

## URL base

Establezca la URL de la aplicación para su entorno una vez y úsela en cada ejemplo. La producción suele utilizar `https://app.nudgen.net`; el desarrollo local comúnmente usa `http://localhost:3000`.

```bash
export NUDGEN_APP_URL="https://app.nudgen.net"
```

## Autenticación

### Token de acceso personal

Cree una PAT en **Configuración** → **Claves API**. Úselo para contactos, administración de campañas, configuración de marca y generación de IA.

```bash
Authorization: Bearer $NUDGEN_PAT
```

Las PAT se muestran solo una vez. Guárdelos de forma segura y revoque cualquier token antiguo o expuesto desde **Configuración** → **Claves de API**.

### Clave de API de activación de equipo

Una clave de API de activación de equipo comienza con `ndg_team_` y tiene un alcance limitado de `campaigns:trigger`. Solo puede activar campañas de por vida; una PAT no puede activarlas.

Solo los propietarios y administradores del espacio de trabajo pueden crear, rotar o revocar estas claves. De forma predeterminada, una clave caduca después de 90 días. Configure `expiresInDays` en `null` para crear una clave que no caduque.

```bash
curl -X POST "$NUDGEN_APP_URL/api/v1/settings/team-api-keys" \
  -H "Authorization: Bearer $NUDGEN_PAT" \
  -H "Content-Type: application/json" \
  --data '{"name":"Order service production","expiresInDays":90}'
```

La respuesta `201` contiene el texto sin formato `key` exactamente una vez. Guárdelo en un administrador secreto del lado del servidor. Las respuestas posteriores exponen solo `keyPrefix`.

| Método | Punto final | Descripción |
| --- | --- | --- |
| `POST` | `/api/v1/settings/team-api-keys` | Cree una clave API de activación de equipo. |
| `GET` | `/api/v1/settings/team-api-keys` | Enumere las claves API de activación del equipo. |
| `POST` | `/api/v1/settings/team-api-keys/:id` | Gire una clave activa y vigente. |
| `DELETE` | `/api/v1/settings/team-api-keys/:id` | Revocar una clave. |

## Campañas de por vida

Las campañas de por vida se activan mediante eventos: cada activador aceptado crea como máximo una ejecución y envía un empujón al contacto proporcionado. Consulte [Usar campañas de por vida](/es/campaigns/lifetime) para obtener información sobre el flujo de trabajo del panel y orientación sobre contratos variables.

### Crear una campaña de por vida

Crear campañas de por vida como `draft`. No envíe `sendNow: true`, `status: "active"` o `status: "scheduled"`; En su lugar, active la campaña con su punto final del ciclo de vida.

```bash
curl -X POST "$NUDGEN_APP_URL/api/v1/campaigns" \
  -H "Authorization: Bearer $NUDGEN_PAT" \
  -H "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "name": "Order confirmation",
  "type": "lifetime",
  "status": "draft",
  "goal": "Confirm an order and direct the customer to its details.",
  "subject": "Your order {{data.order_id}} was received",
  "html": "<p>Hello {{contact.firstName}},</p><p>Order {{data.order_id}} totals {{data.total}} VND.</p><p><a href=\"{{data.order_url}}\">View your order</a></p>",
  "link": "https://example.com/orders",
  "variableManifest": [
    { "path": "data.order_id", "type": "string", "required": true, "description": "Order ID" },
    { "path": "data.total", "type": "number", "required": true, "description": "Order total in VND" },
    { "path": "data.order_url", "type": "url", "required": true, "description": "Order details URL" }
  ],
  "generatedVariableManifest": [
    { "path": "data.order_id", "type": "string", "required": true, "description": "Order ID" },
    { "path": "data.total", "type": "number", "required": true, "description": "Order total in VND" },
    { "path": "data.order_url", "type": "url", "required": true, "description": "Order details URL" }
  ]
}
JSON
```

`variableManifest` define hasta 100 variables `data.*`. Debe incluir todos los tokens `data.*` utilizados en el asunto o HTML. Los valores predeterminados deben coincidir con el tipo declarado y una variable utilizada en HTML `href` debe tener el tipo `url`.

Cuando genere contenido de correo electrónico, guarde el `generatedVariableManifest` coincidente. Nudgen bloquea la activación si difiere del manifiesto actual o si los parámetros declarados requeridos no están en el correo electrónico.

### Cambiar el ciclo de vida

| Método | Punto final | Autenticación | Descripción |
| --- | --- | --- | --- |
| `PATCH` | `/api/v1/campaigns/:campaignId/lifecycle` | palmadita | Cambie una campaña de por vida a `active`, `paused` o `archived`. |

```bash
curl -X PATCH "$NUDGEN_APP_URL/api/v1/campaigns/$CAMPAIGN_ID/lifecycle" \
  -H "Authorization: Bearer $NUDGEN_PAT" \
  -H "Content-Type: application/json" \
  --data '{"status":"active"}'
```

Las transiciones válidas son `draft → active → paused → active` y `active|paused → archived`. Pausar o archivar cancela las ejecuciones que aún son `pending` o `queued` y libera sus reservas de cuota. Es posible que aún se envíe una ejecución que ya se está procesando.

### Activar un empujón

| Método | Punto final | Autenticación | Descripción |
| --- | --- | --- | --- |
| `POST` | `/api/v1/campaigns/:campaignId/triggers` | Clave API de activación del equipo | Cree una ejecución de evento y ponga en cola un empujón. |

```bash
curl -X POST "$NUDGEN_APP_URL/api/v1/campaigns/$CAMPAIGN_ID/triggers" \
  -H "Authorization: Bearer $NUDGEN_TEAM_API_KEY" \
  -H "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "eventId": "order_123",
  "eventName": "order.created",
  "occurredAt": "2026-08-23T10:00:00Z",
  "contact": {
    "email": "an@example.com",
    "externalId": "customer_456",
    "name": "An Nguyen",
    "phone": "+84901234567",
    "metadata": { "company": "Nudgen" }
  },
  "data": {
    "order_id": "order_123",
    "total": 490000,
    "order_url": "https://example.com/orders/order_123"
  }
}
JSON
```

| Campo | Tipo | Requerido | Límites y comportamiento |
| --- | --- | --- | --- |
| `eventId` | cadena | Sí | 1–128 caracteres. Clave de idempotencia única dentro de la campaña; reutilícelo para reintentos. |
| `eventName` | cadena | No | De 1 a 100 caracteres, por ejemplo `order.created`. |
| `occurredAt` | Fecha y hora ISO 8601 | No | Hora del evento fuente. |
| `contact.email` | correo electrónico | Sí | En minúsculas. Nudgen crea o actualiza el contacto por correo electrónico. |
| `contact.externalId` | cadena | No | Entre 1 y 200 caracteres y no puede pertenecer a otro correo electrónico de contacto en el espacio de trabajo. |
| `contact.name` | cadena | No | Hasta 200 caracteres. |
| `contact.phone` | cadena | No | Hasta 50 caracteres. |
| `contact.metadata` | objeto | No | Datos adicionales del perfil de contacto. |
| `data` | objeto | Sí | Debe coincidir con `variableManifest`; máximo 32 KiB. |

Todo el cuerpo de la solicitud está limitado a 64 KiB, el anidamiento JSON en ocho niveles y las claves no seguras como `__proto__`, `constructor` y `prototype` se rechazan.

Un nuevo activador devuelve `201` con `{ "execution": { "id": "...", "status": "queued" }, "duplicate": false }`. Reutilizar un `eventId` devuelve la ejecución existente con `200` y `duplicate: true`.

### Listar ejecuciones

| Método | Punto final | Autenticación | Descripción |
| --- | --- | --- | --- |
| `GET` | `/api/v1/campaigns/:campaignId/executions` | palmadita | Enumere las ejecuciones de campañas de por vida. |

```bash
curl "$NUDGEN_APP_URL/api/v1/campaigns/$CAMPAIGN_ID/executions?limit=25&status=sent&search=an@example.com" \
  -H "Authorization: Bearer $NUDGEN_PAT"
```

Utilice `limit` del 1 al 100 (predeterminado `25`), `cursor` para la página siguiente, `status` para filtrar por estado de ejecución y `search` para coincidir. un correo electrónico o una identificación externa. La respuesta incluye `executions` y `nextCursor`.

## Errores, reintentos y límites de velocidad

Los activadores de por vida permiten 600 solicitudes por minuto para cada clave API de activación del equipo. Las respuestas incluyen `x-ratelimit-limit`, `x-ratelimit-remaining` y `x-ratelimit-reset`. Una respuesta `429` también incluye `Retry-After`.

| Estado | Significado | Qué hacer |
| --- | --- | --- |
| `200` | Duplicado `eventId` | Utilice la ejecución devuelta; no enviar de nuevo. |
| `201` | Nueva ejecución en cola | Espere a que el trabajador lo procese. |
| `400` | JSON, cuerpo o campo básico no válido | Corrija la carga útil; no lo vuelva a intentar sin cambios. |
| `401` | Clave faltante, no válida, revocada, vencida o con alcance incorrecto | Gire o corrija la configuración de la clave. |
| `402` / `403` | Cuota o suscripción impide escrituras | Resolver el problema de cuota o suscripción. Los errores de cuota incluyen `code`, `required`, `available` y `checkoutUrl`. |
| `404` | Falta la campaña o está fuera del espacio de trabajo de la clave | Verifique el ID y la clave de la campaña. |
| `409` | La campaña no está activa/no es de por vida o hay conflictos de identidad de contacto | Activar la campaña o corregir la identidad del contacto. |
| `413` | La solicitud supera los 64 KiB | Reducir el tamaño de la carga útil. |
| `415` | Falta `Content-Type: application/json` | Agregue el encabezado requerido. |
| `422` | `data` no coincide con la variable manifiesto | Corregir los datos; Inspeccione `details` en busca de rutas y códigos de error. |
| `429` | Límite de tarifa excedido | Espere a `Retry-After`, luego vuelva a intentarlo con el mismo `eventId`. |
| `503` | La ejecución no se pudo poner en cola | Vuelva a intentarlo con retroceso y el mismo `eventId`. |

Para `429`, `503` y errores de red, vuelva a intentarlo con un retroceso exponencial y el mismo `eventId`. El trabajo en cola es determinista para una ejecución, por lo que los reintentos no crean correos electrónicos duplicados.
