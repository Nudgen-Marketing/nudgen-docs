## Overview

Nudgen hosts an MCP server at your app origin's `/api/mcp` endpoint. Connect an MCP client that supports Streamable HTTP and OAuth. Sign in to Nudgen in your browser, choose a workspace, and approve the permissions the client requests. Your connection stays bound to that workspace, even if you later switch workspaces in the dashboard.

## Why this matters

Your assistant can read contacts and campaigns, draft content, and prepare a campaign for launch without handling a dashboard session or a Personal Access Token. You review each real send or schedule in your browser before it can proceed.

## Connect your client

The production endpoint is:

```text
https://app.nudgen.net/api/mcp
```

Add it as a **remote HTTP MCP server** in a client with OAuth support. The client discovers Nudgen's authorization server from the endpoint and opens a browser sign-in and consent flow. Select the workspace you want the client to access and approve only the scopes it needs.

For Codex CLI, use:

```bash
codex mcp add nudgen --url "https://app.nudgen.net/api/mcp" --oauth-resource "https://app.nudgen.net/api/mcp"
codex mcp login nudgen --scopes campaigns:read,campaigns:write,campaigns:send
```

If you only need to inspect data, request `campaigns:read`. Add `campaigns:write` for contacts, campaign drafts, brand changes, and AI drafts. Add `campaigns:send` only when the client needs to request launch approval. The `campaigns:send` scope alone never sends a campaign.

<Note>
  Personal Access Tokens authenticate the [Developer API](/en/agents/api), but they do not authenticate `/api/mcp`. An MCP client must complete OAuth sign-in.
</Note>

## Available tools

| Task | Tools |
| --- | --- |
| Inspect your workspace | `get_current_user`, `list_contacts`, `list_campaigns`, `get_campaign`, `get_campaign_stats`, `get_brand_settings` |
| Create and edit | `create_contact`, `create_campaign`, `update_brand_settings`, `generate_email_draft` |
| Request and complete a launch | `prepare_campaign_launch`, `launch_campaign` |

`create_campaign` saves a **draft one-time campaign**. It cannot send or schedule directly. `get_campaign` lets you check the subject, content, link, audience, and sender before launch.

### Approve a campaign launch

1. Ask the assistant to inspect the draft with `get_campaign`.
2. Ask it to call `prepare_campaign_launch` with the campaign ID and the exact send-now or scheduled time you want. This returns a one-time approval URL; no email is sent yet.
3. Open the URL, review the workspace, recipient estimate, content, sender, and timing, then click **Approve launch**.
4. Return to the client so it can call `launch_campaign` with the same campaign ID, timing, and `approvalId`.

An approval expires after **10 minutes** and can be used once. If the campaign or sender changes, request a new approval. Nudgen checks sender readiness, eligible recipients, subscription, quota, and queue availability again when launching. Delivery begins only after the campaign worker processes the launch.

<Warning>
  Approving and completing `launch_campaign` can send real email. Use the dashboard's test-send flow to check an inbox preview before approving a real audience.
</Warning>

## Manage access

Open **Settings** → **API Keys** → **Connected MCP apps** to see each connected client's workspace and scopes. Revoke a connection there if it should no longer have access. Revocation disables its tokens and pending launch approvals. You can reconnect through OAuth later.

OAuth grants last at most 90 days. Losing access to a workspace also prevents the client from using that workspace's connection.

## Troubleshooting

| Symptom | What to do |
| --- | --- |
| Sign-in does not start | Confirm the client supports remote Streamable HTTP MCP with OAuth and uses the app endpoint above. |
| A tool needs more permission | Reconnect and approve the needed scope for that workspace. |
| Contact search asks you to narrow results | Search scans at most 5,000 contacts after tag and status filters because contact names and addresses are encrypted. Narrow the filters. |
| Launch approval expired or the campaign changed | Request a new approval and review the current campaign and sender. |
| A launch is blocked | Check the campaign's draft status, sender readiness, eligible contacts, plan quota, and [sending domain](/en/settings/sending-domains). |

For scripts using bearer tokens and direct REST endpoints, see the [Developer API](/en/agents/api).
