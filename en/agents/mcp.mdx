## Overview

Nudgen hosts an MCP server at your app origin's `/mcp` endpoint. It speaks MCP `2026-07-28` over Streamable HTTP and requires OAuth 2.1. Connect a client that supports that transport. Sign in to Nudgen in your browser, choose a workspace, and approve the permissions the client requests. Your connection stays bound to that workspace, even if you later switch workspaces in the dashboard.

## Why this matters

Your assistant can inspect contacts, find businesses, and create campaign drafts. Authorize sending or scheduling in chat, and the assistant runs the action directly without a browser approval link.

## Connect your client

The production endpoint is:

```text
https://app.nudgen.net/mcp
```

Add it as a **remote HTTP MCP server** in a client with OAuth support. The client discovers Nudgen's authorization server from the endpoint and opens a browser sign-in and consent flow. Select the workspace you want the client to access and approve only the scopes it needs.

Discovery documents:

| Document | URL |
| --- | --- |
| Protected resource metadata | `https://app.nudgen.net/.well-known/oauth-protected-resource/mcp` |
| Authorization server | `https://app.nudgen.net/mcp-oauth` |
| Server card | `https://app.nudgen.net/.well-known/mcp/server-card.json` |

The authorization server uses authorization code with PKCE S256, resource binding, and refresh-token rotation. It accepts Client ID Metadata Documents and dynamic client registration.

For Codex CLI, use:

```bash
codex mcp add nudgen --url "https://app.nudgen.net/mcp" --oauth-resource "https://app.nudgen.net/mcp"
codex mcp login nudgen --scopes campaigns:read,campaigns:write,campaigns:send
```

If a client named `nudgen` is already configured, update that entry with the `/mcp` URL.

| Scope | What it allows |
| --- | --- |
| `campaigns:read` | Inspect the workspace, contacts, campaigns, brand settings, and search map leads. |
| `campaigns:write` | Create contacts and draft campaigns, update brand settings, generate AI drafts, and import map leads. |
| `campaigns:send` | Launch a draft campaign. |

Request `campaigns:read` for inspection, `campaigns:write` for drafts and edits, and `campaigns:send` for authorized email actions. OAuth consent remains required.

<Note>
  Personal Access Tokens authenticate the [Developer API](/en/agents/api), but they do not authenticate `/mcp`. An MCP client must complete OAuth sign-in.
</Note>

## Available tools

| Task | Tools | Scope |
| --- | --- | --- |
| Inspect your workspace | `get_current_user`, `list_contacts`, `list_campaigns`, `get_campaign`, `get_campaign_stats`, `get_brand_settings` | `campaigns:read` |
| Find nearby businesses | `search_map_leads`, `retry_map_leads_enrichment` | `campaigns:read` |
| Create and edit | `create_contact`, `create_campaign`, `update_brand_settings`, `generate_email_draft`, `import_map_leads` | `campaigns:write` |
| Launch a draft campaign | `launch_campaign`, `send_test_email`, `activate_lifetime_campaign`, `trigger_lifetime_campaign` | `campaigns:send` |

`create_campaign` saves a **draft campaign (`one-time`, `drip`, or `lifetime`)**. It cannot send or schedule directly. `get_campaign` lets you check the subject, content, link, audience, and sender before launch.

The server also exposes read-only resources on `campaigns:read`:

| Resource | Contents |
| --- | --- |
| `nudgen://api-catalog` | Names and descriptions of the hosted tools. |
| `nudgen://team/brand` | Brand settings for the connected workspace. |
| `nudgen://campaigns/{id}/summary` | Delivery stats for one campaign. Replace `{id}` with the campaign ID. |

### Find and import map leads

1. Ask the assistant to call `search_map_leads` with a location and business keywords, such as a city and `marketing agency`.
2. Optional filters are `radiusKm` (1–100), `lat` and `lng`, and `emailOnly` to keep businesses that publish an email.
3. When the result includes `nextPageToken`, pass it as `pageToken` to load another page.
4. Ask the assistant to call `import_map_leads` with the same location and keywords, plus the lead objects to save. Each call accepts up to 200 leads.

Import writes contacts in the connected workspace. Leads without an email are skipped. A lead that already exists is updated.

### Launch a draft campaign

1. Review the campaign name, subject, content, effective sender, audience estimate, and timing with `get_campaign`.
2. Authorize the action in chat. The assistant calls `launch_campaign` directly with the campaign ID and either `sendNow: true` or `scheduledAt` with a future timestamp and timezone. Do not supply contradictory timing arguments. Existing authorization does not require another confirmation.
3. Review the returned status, scheduled time, and dashboard link. Queued or scheduled does not mean delivered. Check `get_campaign` and `get_campaign_stats` before retrying an uncertain outcome.

Nudgen still checks workspace permissions, sender readiness, eligible recipients, subscription, quota, campaign version, and queue availability. Creation and editing remain draft-only; delivery requires the campaign worker.

## Manage access

Open **Settings** → **API Keys** → **Connected MCP apps** to inspect and revoke access. Revocation disables the connection tokens. Losing workspace membership also blocks access. Reconnect through OAuth when needed.

## Troubleshooting

| Symptom | What to do |
| --- | --- |
| Sign-in does not start | Confirm the client supports remote Streamable HTTP MCP with OAuth and uses `https://app.nudgen.net/mcp`. |
| A tool needs more permission | Reconnect and approve the needed scope for that workspace. |
| Contact search asks you to narrow results | Search matches names and email addresses, and scans at most 5,000 contacts after tag and status filters. Narrow the filters. |
| Map lead import skips a business | Only leads with an email are saved. Search again with `emailOnly` set to true, or pick leads that already include an email. |
| Old approval link or tool | Refresh tool discovery and authorize the direct action in chat; old links cannot launch campaigns. |
| A launch is blocked | Check the campaign's draft status, sender readiness, eligible contacts, plan quota, and [sending domain](/en/settings/sending-domains). |

For scripts using bearer tokens and direct REST endpoints, see the [Developer API](/en/agents/api).

### Search radius and enrichment

API and MCP searches default to 5 km and accept an explicit integer `radiusKm` from 1 to 100. They do not show the dashboard confirmation dialog. Keep the same search inputs when passing `nextPageToken` as `pageToken`; a page can contain no matching leads and still have another page.

Contact enrichment may finish after businesses first appear. `enrichmentPending` marks unfinished website research. Review `businessSummary` and `businessSources` when available; imported business context can support personalized campaign introductions. A missing email can mean research is still pending.

If `enrichmentRetryToken` is present, call `retry_map_leads_enrichment` with `token` to retry pending website research. It requires `campaigns:read`, is bound to the connected workspace, expires after 15 minutes, and can be used once. Merge returned leads by `placeId` before importing. `emailOnly` filters the current response; pending leads may appear after retry.

## Edit drafts and product coverage

Use `update_campaign` to edit an existing draft and `delete_campaign` to delete a draft. Both require `campaigns:write`; neither sends or schedules email. New product domains require their own OAuth permissions. Reconnect and approve those permissions when requested.

Tool discovery lists the available tools and their arguments. Browser handoffs do not perform the action: complete payments, provider authorization, invitation sending, workspace switching, and sensitive payout settings in the browser. Your MCP connection remains bound to the workspace you authorized. Administrative functions, credentials, webhooks, tracking callbacks, and the internal assistant are excluded.

Use `get_api_capabilities` to inspect API coverage. After authorization in chat, call `send_test_email`, `activate_lifetime_campaign`, or `trigger_lifetime_campaign` directly. Test sends go only to the account email. Lifetime activation enables future automated delivery. No browser approval or approval ID is required. Check status or execution history before retrying an uncertain outcome.
