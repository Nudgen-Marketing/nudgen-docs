## Übersicht

Nudgen stellt unter `/mcp` Ihrer App-Origin einen MCP-Server bereit. Er unterstützt MCP `2026-07-28` über Streamable HTTP und benötigt OAuth 2.1. Melden Sie sich im Browser an und bestätigen Sie die angeforderten Berechtigungen. Wenn verfügbar, wählen Sie einen Workspace oder erlauben ausdrücklich den Zugriff auf alle aktuellen und zukünftigen Workspaces, denen Sie angehören. Ein Wechsel im Dashboard ändert den MCP-Standard nicht.

## Mit mehreren Workspaces arbeiten

Bestehende Verbindungen bleiben auf ihren ursprünglichen Workspace beschränkt, bis Sie sich erneut verbinden und den erweiterten Zugriff bestätigen. Bei Zugriff auf alle Workspaces werden neue Mitgliedschaften automatisch verfügbar. Nach Ende einer Mitgliedschaft werden weitere Aktionen dort blockiert. Rollen, Abonnements und Kontingente gelten weiterhin pro Workspace.

Mit `list_workspaces`, `page` und `pageSize` erhalten Sie IDs, Namen, Slugs, Rollen und den Standard-Workspace. Dafür ist `teams:read` erforderlich. Geben Sie bei einem Workspace-Werkzeug `workspaceId` an, um nur diesen Aufruf auf einen anderen Workspace zu richten. Ohne Angabe gilt der Verbindungsstandard. Verwenden Sie beim Prüfen und Versenden einer Kampagne dieselbe explizite Workspace-ID.

Wählen Sie den Standard bei der OAuth-Zustimmung. Ändern Sie ihn unter **Einstellungen → API-Schlüssel → Verbundene MCP-Apps** oder mit `set_default_workspace`, `workspaceId` und `teams:write`. Die Änderung gilt für alle Chats mit dieser Verbindung. Ein einzelner Aufruf mit anderer ID ändert den Standard nicht. Ist der Standard gelöscht oder nicht mehr zugänglich, geben Sie eine andere ID an oder aktualisieren Sie den Standard. Nudgen wählt nie stillschweigend einen Ersatz.

```jsonl
{"name":"list_workspaces","arguments":{"page":1,"pageSize":25}}
{"name":"list_campaigns","arguments":{"workspaceId":"workspace_b"}}
{"name":"set_default_workspace","arguments":{"workspaceId":"workspace_b"}}
```

Bestehende Ressourcen-URIs verwenden den Standard-Workspace. Diese Vorlagen wählen einen Workspace ausdrücklich:

```text
nudgen://workspaces/{workspaceId}/brand
nudgen://workspaces/{workspaceId}/campaigns/{id}/summary
```

## Warum das wichtig ist

Ihr Assistent kann Kontakte prüfen, Unternehmen finden und Kampagnenentwürfe erstellen. Geben Sie Versand oder Planung im Chat frei. Der Assistent führt die Aktion direkt ohne Freigabelink im Browser aus.

## Client verbinden

Der Produktionsendpunkt lautet:

```text
https://app.nudgen.net/mcp
```

Fügen Sie ihn in einem Client mit OAuth-Unterstützung als **Remote-HTTP-MCP-Server** hinzu. Der Client ermittelt den Autorisierungsserver von Nudgen über den Endpunkt und öffnet einen Anmelde- und Zustimmungsablauf im Browser. Wählen Sie den Workspace aus, auf den der Client zugreifen soll, und genehmigen Sie nur die benötigten Bereiche.

Discovery-Dokumente:

| Dokument | URL |
| --- | --- |
| Metadaten der geschützten Ressource | `https://app.nudgen.net/.well-known/oauth-protected-resource/mcp` |
| Autorisierungsserver | `https://app.nudgen.net/mcp-oauth` |
| Serverkarte | `https://app.nudgen.net/.well-known/mcp/server-card.json` |

Der Autorisierungsserver verwendet den Authorization Code Flow mit PKCE S256, Ressourcenbindung und Refresh-Token-Rotation. Er akzeptiert Client-ID-Metadatendokumente und die dynamische Clientregistrierung.

Verwenden Sie für Codex CLI:

```bash
codex mcp add nudgen --url "https://app.nudgen.net/mcp" --oauth-resource "https://app.nudgen.net/mcp"
codex mcp login nudgen --scopes campaigns:read,campaigns:write,campaigns:send,teams:read,teams:write
```

Wenn bereits ein Client namens `nudgen` konfiguriert ist, aktualisieren Sie diesen Eintrag mit der URL `/mcp`.

| Bereich | Zulässige Aktionen |
| --- | --- |
| `campaigns:read` | Workspace, Kontakte, Kampagnen und Markeneinstellungen prüfen sowie Karten-Leads suchen. |
| `campaigns:write` | Kontakte und Kampagnenentwürfe erstellen, Markeneinstellungen aktualisieren, KI-Entwürfe generieren und Karten-Leads importieren. |
| `campaigns:send` | Kampagnenentwurf starten. |

Nutzen Sie `campaigns:read` zum Lesen, `campaigns:write` für Entwürfe und Änderungen und `campaigns:send` für freigegebene E-Mail-Aktionen. OAuth-Zustimmung bleibt erforderlich.

<Note>
  Persönliche Zugriffstoken authentifizieren die [Entwickler-API](/de/agents/api), aber nicht `/mcp`. Ein MCP-Client muss die OAuth-Anmeldung abschließen.
</Note>

## Verfügbare Tools

| Aufgabe | Tools | Bereich |
| --- | --- | --- |
| Workspace prüfen | `get_current_user`, `list_contacts`, `list_campaigns`, `get_campaign`, `get_campaign_stats`, `get_brand_settings` | `campaigns:read` |
| Unternehmen in der Nähe finden | `search_map_leads`, `retry_map_leads_enrichment` | `campaigns:read` |
| Erstellen und bearbeiten | `create_contact`, `create_campaign`, `update_brand_settings`, `generate_email_draft`, `import_map_leads` | `campaigns:write` |
| Kampagnenentwurf starten | `launch_campaign`, `send_test_email`, `activate_lifetime_campaign`, `trigger_lifetime_campaign` | `campaigns:send` |

`create_campaign` speichert eine **Kampagne als Entwurf (`one-time`, `drip` oder `lifetime`)**. Das Tool kann sie nicht direkt versenden oder planen. Mit `get_campaign` können Sie vor dem Start Betreff, Inhalt, Link, Zielgruppe und Absender prüfen.

Der Server stellt außerdem schreibgeschützte Ressourcen unter `campaigns:read` bereit:

| Ressource | Inhalt |
| --- | --- |
| `nudgen://api-catalog` | Namen und Beschreibungen der bereitgestellten Tools. |
| `nudgen://team/brand` | Markeneinstellungen des verbundenen Workspace. |
| `nudgen://campaigns/{id}/summary` | Zustellungsstatistiken für eine Kampagne. Ersetzen Sie `{id}` durch die Kampagnen-ID. |

### Karten-Leads finden und importieren

1. Bitten Sie den Assistenten, `search_map_leads` mit einem Standort und Suchbegriffen für Unternehmen aufzurufen, beispielsweise mit einer Stadt und `marketing agency`.
2. Optionale Filter sind `radiusKm` (1–100), `lat` und `lng` sowie `emailOnly`, um nur Unternehmen zu behalten, die eine E-Mail-Adresse veröffentlichen.
3. Wenn das Ergebnis `nextPageToken` enthält, übergeben Sie es als `pageToken`, um eine weitere Seite zu laden.
4. Bitten Sie den Assistenten, `import_map_leads` mit demselben Standort und denselben Suchbegriffen sowie den zu speichernden Lead-Objekten aufzurufen. Jeder Aufruf akzeptiert bis zu 200 Leads.

Beim Import werden Kontakte im verbundenen Workspace gespeichert. Leads ohne E-Mail-Adresse werden übersprungen. Ein bereits vorhandener Lead wird aktualisiert.

### Kampagnenentwurf starten

1. Prüfen Sie Kampagnenname, Betreff, Inhalt, tatsächlichen Absender, geschätzte Empfängerzahl und Zeitpunkt mit `get_campaign`.
2. Geben Sie die Aktion im Chat frei. Der Assistent ruft `launch_campaign` direkt mit Kampagnen-ID und entweder `sendNow: true` oder `scheduledAt` mit einem zukünftigen Zeitstempel und Zeitzone auf. Widersprüchliche Zeitangaben sind unzulässig. Eine vorhandene Freigabe braucht keine erneute Bestätigung.
3. Prüfen Sie Status, geplanten Zeitpunkt und Dashboard-Link im Ergebnis. Eingereiht oder geplant bedeutet noch nicht zugestellt. Prüfen Sie bei unklarem Ergebnis vor einem erneuten Versuch `get_campaign` und `get_campaign_stats`.

Nudgen prüft weiterhin Workspace-Berechtigungen, Absenderbereitschaft, geeignete Empfänger, Abonnement, Kontingent, Kampagnenversion und Warteschlange. Erstellung und Bearbeitung speichern nur Entwürfe; der Versand benötigt den Kampagnen-Worker.

## Zugriff verwalten

Unter **Einstellungen → API-Schlüssel → Verbundene MCP-Apps** können Sie Zugriffe prüfen, den Standard ändern oder die Verbindung trennen. Das Trennen einer Verbindung für mehrere Workspaces widerruft deren Tokens und ausstehende Autorisierungscodes für alle Workspaces. Separate REST-Verbindungen bleiben bestehen. REST OAuth und der Assistent in der App behalten ihre bisherigen Workspace-Grenzen.

## Fehlerbehebung

| Symptom | Vorgehensweise |
| --- | --- |
| Die Anmeldung startet nicht | Prüfen Sie, ob der Client Remote-MCP über Streamable HTTP mit OAuth unterstützt und `https://app.nudgen.net/mcp` verwendet. |
| Ein Tool benötigt weitere Berechtigungen | Stellen Sie die Verbindung erneut her und genehmigen Sie den benötigten Bereich für diesen Workspace. |
| Die Kontaktsuche fordert Sie auf, die Ergebnisse einzugrenzen | Die Suche gleicht Namen und E-Mail-Adressen ab und durchsucht nach Anwendung von Tag- und Statusfiltern höchstens 5.000 Kontakte. Grenzen Sie die Filter ein. |
| Beim Import von Karten-Leads wird ein Unternehmen übersprungen | Es werden nur Leads mit einer E-Mail-Adresse gespeichert. Suchen Sie erneut mit `emailOnly` auf `true` oder wählen Sie Leads aus, die bereits eine E-Mail-Adresse enthalten. |
| Alter Freigabelink oder altes Tool | Aktualisieren Sie die Tool-Liste und geben Sie die direkte Aktion im Chat frei; alte Links können keine Kampagnen starten. |
| Ein Start wird blockiert | Prüfen Sie den Entwurfsstatus der Kampagne, die Absenderbereitschaft, berechtigte Kontakte, das Plankontingent und die [Versanddomain](/de/settings/sending-domains). |

Informationen zu Skripten mit Bearer-Token und direkten REST-Endpunkten finden Sie in der [Entwickler-API](/de/agents/api).

### Suchradius und Anreicherung

API- und MCP-Suchen verwenden standardmäßig 5 km und akzeptieren eine ganze Zahl `radiusKm` von 1 bis 100, ohne Dashboard-Bestätigung. Behalten Sie die Suchparameter bei, wenn Sie `nextPageToken` als `pageToken` übergeben. Auch eine leere Seite kann eine Folgeseite haben.

`enrichmentPending` kennzeichnet noch laufende Website-Recherche. Prüfen Sie verfügbare `businessSummary` und `businessSources`. Importierter Geschäftskontext kann personalisierte Kampagneneinleitungen unterstützen. Eine fehlende E-Mail kann noch recherchiert werden.

Bei `enrichmentRetryToken` rufen Sie `retry_map_leads_enrichment` mit `token` und `campaigns:read` auf. Der Token gilt für den verbundenen Workspace, läuft nach 15 Minuten ab und ist einmal verwendbar. Ergebnisse vor dem Import anhand von `placeId` zusammenführen. `emailOnly` filtert die aktuelle Antwort; weitere Leads können nach dem Wiederholen erscheinen.

## Entwürfe bearbeiten und Funktionsumfang

Mit `update_campaign` bearbeitest du einen vorhandenen Entwurf; mit `delete_campaign` löschst du ihn. Beide benötigen `campaigns:write` und versenden oder planen keine E-Mails. Neue Funktionsbereiche benötigen eigene OAuth-Berechtigungen. Verbinde dich erneut und bestätige diese Berechtigungen, wenn du dazu aufgefordert wirst.

Die Werkzeugliste zeigt verfügbare Werkzeuge und Argumente. Browser-Übergaben führen keine Aktion aus. Nutzen Sie den Browser für Zahlungen, Anbieterautorisierung, Einladungen, das Erstellen/Löschen/Beitreten von Workspaces und vertrauliche Auszahlungseinstellungen. MCP-Zielauswahl und Standardänderungen wechseln den Dashboard-Workspace nicht. Administration, Zugangsdaten, Webhooks, Tracking-Callbacks und der interne Assistent sind ausgeschlossen.

Prüfen Sie mit `get_api_capabilities` die API-Abdeckung. Rufen Sie nach Freigabe im Chat `send_test_email`, `activate_lifetime_campaign` oder `trigger_lifetime_campaign` direkt auf. Tests gehen nur an die Konto-E-Mail. Lifetime-Aktivierung ermöglicht künftigen automatischen Versand. Browserfreigabe und Freigabe-ID entfallen. Prüfen Sie bei unklarem Ergebnis vor einem erneuten Versuch Status oder Ausführungsverlauf.
