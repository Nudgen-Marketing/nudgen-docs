## 概览

Nudgen 在应用来源的 `/mcp` 端点托管 MCP 服务器，支持通过 Streamable HTTP 使用 MCP `2026-07-28`，并要求 OAuth 2.1。在浏览器中登录并批准所需权限。功能可用时，你可以选择一个工作区，或明确授权访问你当前及未来加入的所有工作区。在仪表盘切换工作区不会改变 MCP 的默认工作区。

## 使用多个工作区

现有连接仍限于原先的工作区，直到你重新连接并批准更广泛的访问。授权所有工作区后，新加入的工作区会自动可用；失去成员资格后，该工作区中的后续操作将被阻止。角色、订阅和配额仍分别按工作区执行。

使用带有 `page` 和 `pageSize` 的 `list_workspaces` 查看工作区 ID、名称、slug、角色及默认状态。需要 `teams:read` 权限。为工作区工具调用添加 `workspaceId` 可仅为本次操作指定目标；省略时使用连接的默认工作区。检查和发送同一营销活动时，请明确传入相同的工作区 ID。

在 OAuth 授权时选择默认工作区。通过 **设置 → API 密钥 → 已连接的 MCP 应用**，或使用 `workspaceId` 和 `teams:write` 权限调用 `set_default_workspace` 来修改。此修改影响使用该连接的所有聊天；单次调用指定目标不会修改默认值。如果默认工作区被删除或无法访问，请明确指定其他工作区或更新默认值。Nudgen 不会悄悄选择替代工作区。

```jsonl
{"name":"list_workspaces","arguments":{"page":1,"pageSize":25}}
{"name":"list_campaigns","arguments":{"workspaceId":"workspace_b"}}
{"name":"set_default_workspace","arguments":{"workspaceId":"workspace_b"}}
```

现有资源 URI 使用默认工作区。以下模板可明确指定工作区：

```text
nudgen://workspaces/{workspaceId}/brand
nudgen://workspaces/{workspaceId}/campaigns/{id}/summary
```

## 为什么这很重要

助手可以查看联系人、查找企业并创建活动草稿。在聊天中授权发送或排期后，助手会直接执行，无需浏览器批准链接。

## 连接客户端

生产环境端点为：

```text
https://app.nudgen.net/mcp
```

在支持 OAuth 的客户端中，将其添加为**远程 HTTP MCP 服务器**。客户端会从该端点发现 Nudgen 的授权服务器，并在浏览器中打开登录和授权流程。选择你希望客户端访问的工作区，并且只批准其需要的权限范围。

发现文档：

| 文档 | URL |
| --- | --- |
| 受保护资源元数据 | `https://app.nudgen.net/.well-known/oauth-protected-resource/mcp` |
| 授权服务器 | `https://app.nudgen.net/mcp-oauth` |
| 服务器卡片 | `https://app.nudgen.net/.well-known/mcp/server-card.json` |

授权服务器使用带 PKCE S256 的授权码流程、资源绑定和刷新令牌轮换。它接受客户端 ID 元数据文档和动态客户端注册。

对于 Codex CLI，请使用：

```bash
codex mcp add nudgen --url "https://app.nudgen.net/mcp" --oauth-resource "https://app.nudgen.net/mcp"
codex mcp login nudgen --scopes campaigns:read,campaigns:write,campaigns:send,teams:read,teams:write
```

如果已经配置名为 `nudgen` 的客户端，请将该条目的 URL 更新为 `/mcp`。

| 权限范围 | 允许的操作 |
| --- | --- |
| `campaigns:read` | 查看工作区、联系人、活动和品牌设置，以及搜索地图潜在客户。 |
| `campaigns:write` | 创建联系人和活动草稿、更新品牌设置、生成 AI 草稿，以及导入地图潜在客户。 |
| `campaigns:send` | 启动活动草稿. |

使用 `campaigns:read` 查看数据，`campaigns:write` 创建和编辑草稿，`campaigns:send` 执行已授权的邮件操作。连接时仍需 OAuth 授权。

<Note>
  个人访问令牌用于验证[开发人员 API](/cn/agents/api)，但不能用于验证 `/mcp`。MCP 客户端必须完成 OAuth 登录。
</Note>

## 可用工具

| 任务 | 工具 | 权限范围 |
| --- | --- | --- |
| 查看工作区 | `get_current_user`, `list_contacts`, `list_campaigns`, `get_campaign`, `get_campaign_stats`, `get_brand_settings` | `campaigns:read` |
| 查找附近商家 | `search_map_leads`, `retry_map_leads_enrichment` | `campaigns:read` |
| 创建和编辑 | `create_contact`, `create_campaign`, `update_brand_settings`, `generate_email_draft`, `import_map_leads` | `campaigns:write` |
| 启动活动草稿 | `launch_campaign`, `send_test_email`, `activate_lifetime_campaign`, `trigger_lifetime_campaign` | `campaigns:send` |

`create_campaign` 会保存一个**活动草稿（`one-time`、`drip` 或 `lifetime`）**，不能直接发送或排期。通过 `get_campaign`，你可以在启动前检查主题、内容、链接、受众和发件人。

服务器还通过 `campaigns:read` 提供只读资源：

| 资源 | 内容 |
| --- | --- |
| `nudgen://api-catalog` | 托管工具的名称和说明。 |
| `nudgen://team/brand` | 已连接工作区的品牌设置。 |
| `nudgen://campaigns/{id}/summary` | 单个活动的送达统计数据。请将 `{id}` 替换为活动 ID。 |

### 查找并导入地图潜在客户

1. 让助手使用地点和商家关键词调用 `search_map_leads`，例如某个城市和 `marketing agency`。
2. 可选筛选条件包括 `radiusKm`（1–100）、`lat`、`lng`，以及仅保留公开邮箱商家的 `emailOnly`。
3. 如果结果包含 `nextPageToken`，请将其作为 `pageToken` 传入以加载下一页。
4. 让助手使用相同的地点和关键词调用 `import_map_leads`，并附上要保存的潜在客户对象。每次调用最多接受 200 个潜在客户。

导入操作会在已连接的工作区中写入联系人。没有邮箱的潜在客户会被跳过；已经存在的潜在客户会被更新。

### 启动活动草稿

1. 使用 `get_campaign` 查看活动名称、主题、内容、实际发件人、预计收件人数和发送时间。
2. 在聊天中授权操作。助手直接调用 `launch_campaign`，提供活动 ID，并设置 `sendNow: true` 立即发送，或通过 `scheduledAt` 指定附带时区的未来时间。不要提供相互矛盾的时间参数。已有授权无需再次确认。
3. 查看返回的状态、计划时间和仪表板链接。已排队或已排期不代表已送达。结果不确定时，先查看 `get_campaign` 和 `get_campaign_stats`，再决定是否重试。

Nudgen 仍会检查工作区权限、发件人状态、符合条件的收件人、订阅、配额、活动版本和队列。创建和编辑仅保存草稿；投递需要活动工作进程。

## 管理访问权限

打开 **设置 → API 密钥 → 已连接的 MCP 应用** 查看访问范围、修改默认工作区或断开连接。断开多工作区连接会撤销该连接在所有工作区的令牌和待兑换授权码，不影响独立的 REST 连接。REST OAuth 和应用内助手保持现有工作区边界。

## 故障排除

| 问题 | 处理方法 |
| --- | --- |
| 登录流程未启动 | 确认客户端支持带 OAuth 的远程 Streamable HTTP MCP，并使用 `https://app.nudgen.net/mcp`。 |
| 工具需要更多权限 | 重新连接，并为该工作区批准所需的权限范围。 |
| 联系人搜索要求缩小结果范围 | 搜索会匹配姓名和邮箱地址，并且在应用标签和状态筛选后最多扫描 5,000 个联系人。请缩小筛选范围。 |
| 导入地图潜在客户时跳过某个商家 | 只有包含邮箱的潜在客户才会被保存。请将 `emailOnly` 设为 true 后重新搜索，或选择已经包含邮箱的潜在客户。 |
| 旧的批准链接或工具 | 刷新工具列表并在聊天中授权直接操作；旧链接无法启动活动。 |
| 活动启动被阻止 | 检查活动是否为草稿、发件人是否就绪、是否有符合条件的联系人、套餐配额，以及[发件域名](/cn/settings/sending-domains)。 |

如需在脚本中使用 Bearer 令牌和直接 REST 端点，请参阅[开发人员 API](/cn/agents/api)。

### 搜索半径与信息补充

API和MCP默认使用5 km，接受整数 `radiusKm` 1–100，不显示仪表板确认对话框。将 `nextPageToken` 作为 `pageToken` 传递时保持搜索参数不变。空页面仍可能有下一页。

`enrichmentPending`表示网站调查尚未完成。查看可用的 `businessSummary` 和 `businessSources`。导入的企业背景可帮助个性化营销活动的开场内容。没有邮箱可能是调查仍在等待完成。

收到 `enrichmentRetryToken` 时，使用 `campaigns:read` 权限调用 `retry_map_leads_enrichment` 并传入 `token`。令牌绑定已连接的工作空间，15分钟后过期，只能使用一次。导入前按 `placeId` 合并结果。`emailOnly`筛选当前响应；重试后可能出现更多潜在客户。

## 编辑草稿与功能覆盖

使用 `update_campaign` 编辑现有草稿，使用 `delete_campaign` 删除草稿。两者均需要 `campaigns:write`，不会发送或安排邮件。新增产品领域需要独立的 OAuth 权限。收到提示时，请重新连接并批准这些权限。

工具列表提供可用工具及参数。跳转浏览器本身不会执行操作。付款、提供商授权、邀请、创建/删除/加入工作区及敏感收款设置仍需在浏览器完成。MCP 目标选择和默认值更改不会切换仪表盘工作区。管理功能、凭据、Webhook、跟踪回调和内部助手不在范围内。

使用 `get_api_capabilities` 查看 API 覆盖范围。在聊天中授权后，直接调用 `send_test_email`、`activate_lifetime_campaign` 或 `trigger_lifetime_campaign`。测试邮件仅发送到帐户邮箱。启用 lifetime 会允许后续自动发送。无需浏览器批准或批准 ID。结果不确定时，先检查状态或执行历史，再决定是否重试。
