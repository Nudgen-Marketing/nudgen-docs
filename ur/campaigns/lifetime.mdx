## یہ صفحہ آپ کو کیا کرنے میں مدد کرتا ہے

ایک تاحیات مہم بنائیں جو آپ کے سسٹم سے واقعات کے لیے تیار رہے۔ ہر ایک درست ٹرگر زیادہ سے زیادہ ایک ایگزیکیوشن بناتا ہے اور اس کے پے لوڈ میں رابطے کو ایک جھٹکا بھیجتا ہے۔

## یہ کیوں اہم ہے

آپ مہمات کو بار بار بنائے اور شروع کیے بغیر بروقت، متعلقہ ای میل بھیج سکتے ہیں۔ جب کوئی واقعہ ہوتا ہے تو آپ کا بیک اینڈ کنٹرول کرتا ہے، جب کہ Nudgen ای میل کے مواد، ڈیلیوری، ٹریکنگ اور رابطے کی ترجیحات کو ایک جگہ پر رکھتا ہے۔

## لائف ٹائم مہم کب استعمال کریں

ایونٹ سے چلنے والی ای میل کے لیے لائف ٹائم مہم استعمال کریں، جیسے:

- آرڈر کی تصدیقیں
- ادائیگی کی یاددہانی
- ایونٹ بورڈ پر یا سبسکرپشن پر
 اپ ڈیٹس

ون شاٹ اور ڈرپ مہمات کے برعکس، لائف ٹائم مہم محفوظ شدہ سامعین کو فوری طور پر نہیں بھیجتی ہے۔ اس کے ناظرین ہمیشہ **ٹرگر** ہوتے ہیں۔

## ایک مہم بنائیں اور فعال کریں

<Steps>
 <Step title="Create a Lifetime campaign">
 **مہم** پر جائیں، **نئی مہم** پر کلک کریں، پھر **لائف ٹائم** کا انتخاب کریں۔ مہم کا نام، ہدف، برانڈ کنفیگریشن، اور اختیاری CTA لنک شامل کریں۔
 </Step>
 <Step title="Define runtime parameters">
 ہر وہ قدر شامل کریں جو آپ کا سسٹم بھیجنے کے وقت فراہم کرے گا۔ ایک پیرامیٹر ایک `data.*` متغیر بناتا ہے: مثال کے طور پر، ای میل میں `order_id` `{{data.order_id}}` بن جاتا ہے۔
 </Step>
 <Step title="Create the email">
 تخلیق کریں یا جہاں آپ کا HTML تعلق ہے وہ وقت لکھیں اور پھر HTML کو چلانے کا وقت شامل کریں۔ ای میل کا جائزہ لیں اور اسے فعال کرنے سے پہلے ایک ٹیسٹ بھیجیں۔
 </Step>
 <Step title="Activate the campaign">
اسے بطور مسودہ محفوظ کریں، پھر **فعال کریں** پر کلک کریں۔ Nudgen چیک کرتا ہے کہ مطلوبہ پیرامیٹرز کو ای میل میں دکھایا گیا ہے اور یہ کہ پیرامیٹر کا معاہدہ نسل سے تبدیل نہیں ہوا ہے۔
 </Step>
 <Step title="Create a trigger key">
 **ترتیبات** → **API کیز** پر جائیں اور ایک **ٹیم ٹرگر API کلید** بنائیں۔ `ndg_team_*` راز کو اپنے پسدید یا خفیہ مینیجر میں محفوظ کریں۔ اسے کبھی بھی براؤزر یا موبائل ایپ کوڈ میں نہ رکھیں۔
 </Step>
</Steps>

## رن ٹائم پیرامیٹرز اور ٹیمپلیٹ متغیرات

آپ کا `variableManifest` ای میل ٹیمپلیٹ اور ہر ایک ٹرگر `variableManifest` کے درمیان معاہدہ ہے۔ ایک مہم 100 متغیرات تک کی وضاحت کر سکتی ہے۔

| فیلڈ | قسم | مطلوبہ | تفصیل |
| --- | --- | --- | --- |
| `path` | `data.<name>` | جی ہاں | متغیر راستہ۔ نیسٹڈ پاتھز جیسے `data.order.total` تعاون یافتہ ہیں۔ |
| `type` | `string`, `number`, `boolean`, `date`, یا `url` | جی ہاں | ٹرگر لازمی طور پر ٹائپ کریں۔ ایک `date` ایک درست تاریخ کا سٹرنگ ہونا چاہیے اور `url` HTTP(S) ہونا چاہیے۔ |
| `required` | بولین | جی ہاں | غائب اقدار `422` واپس کرتی ہیں جب تک کہ ڈیفالٹ سیٹ نہ ہو۔ |
| `defaultValue` | سٹرنگ، نمبر، یا بولین | نہیں | فال بیک قدر جو متغیر کی قسم سے مماثل ہونی چاہیے۔ |
| `description` | تار | نہیں | قدر کی وضاحت کریں تاکہ آپ اور Nudgen AI اسے صحیح طریقے سے استعمال کر سکیں۔ |

مثال کے طور پر، ایک ٹیمپلیٹ میں `{{data.order_id}}`، `{{data.total}}`، اور `{{data.order_url}}` استعمال کریں۔ آپ `contact.*`، `event.*`، `brand.*`، اور لیگیسی متغیرات جیسے `{{firstName}}` اور `{{brandName}}` بھی استعمال کر سکتے ہیں۔

Nudgen HTML میں داخل متغیر اقدار سے بچ جاتا ہے۔ ٹیمپلیٹس جاوا اسکرپٹ، ایکسپریشنز، یا لوپس کو سپورٹ نہیں کرتے ہیں۔ `href` میں استعمال ہونے والا کوئی بھی متغیر `data.*` کا متغیر ہونا چاہیے جس کا اعلان `url` قسم کے ساتھ کیا گیا ہے۔

## لائف سائیکل کا نظم کریں

| حیثیت | اس کا کیا مطلب ہے |
| --- | --- |
| **مسودہ** | مہم کو ترتیب دیں اور اس کے ای میل کی جانچ کریں۔ |
| **فعال** | Nudgen توثیق شدہ محرکات کو قبول کرتا ہے۔ |
| **روکا ہوا** | نوڈجن نئے محرکات کو قبول نہیں کرتا ہے۔ آپ اسے دوبارہ شروع کر سکتے ہیں۔ |
| **آرکائیو شدہ** | مہم مستقل طور پر بند ہے اور اسے دوبارہ فعال نہیں کیا جا سکتا۔ |

درست ٹرانزیشنز `draft → active → paused → active` اور `active|paused → archived` ہیں۔

<Note>
موقوف یا آرکائیو کرنا پھانسیوں کو منسوخ کرتا ہے جو ابھی تک زیر التواء یا قطار میں ہیں۔ ایک عملدرآمد پہلے سے پروسیسنگ اب بھی بھیج سکتا ہے ایک فعال مہم میں ترمیم کرنے سے صرف بعد کے محرکات پر اثر پڑتا ہے، نہ کہ پہلے سے موجود عمل پر۔
</Note>

## اپنے بیک اینڈ سے ٹرگر کریں

سورس ایونٹ کی توثیق کرنے کے بعد ایک قابل اعتماد سرور سے ٹرگر اینڈ پوائنٹ کو کال کریں۔ ٹیم ٹرگر API کلید کا استعمال کریں، نہ کہ ذاتی رسائی ٹوکن (PAT)۔

```bash
curl -X POST "$NUDGEN_APP_URL/api/v1/campaigns/$CAMPAIGN_ID/triggers" \
  -H "Authorization: Bearer $NUDGEN_TEAM_API_KEY" \
  -H "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "eventId": "order_123",
  "eventName": "order.created",
  "occurredAt": "2026-08-23T10:00:00Z",
  "contact": {
    "email": "an@example.com",
    "externalId": "customer_456",
    "name": "An Nguyen",
    "metadata": { "company": "Nudgen" }
  },
  "data": {
    "order_id": "order_123",
    "total": 490000,
    "order_url": "https://example.com/orders/order_123"
  }
}
JSON
```

جب آپ کسی ایونٹ کی دوبارہ کوشش کریں تو وہی `eventId` رکھیں۔ Nudgen ایک اور nudge بھیجنے کے بجائے `200` اور `duplicate: true` کے ساتھ موجودہ عمل کو واپس کرتا ہے۔ ایک نیا عمل `201` لوٹاتا ہے۔

## محفوظ طریقے سے انٹیگریٹ کریں

- ویب ہک صارف یا بیک اینڈ سے ٹرگر کریں، اور نوڈجن کو کال کرنے سے پہلے آنے والے ویب ہک کی تصدیق کریں۔ اور وہی `eventId`۔
- `Authorization` ہیڈرز یا پے لوڈز کو لاگ ان نہ کریں جس میں رابطہ کا حساس ڈیٹا ہو۔
- ٹرگر کیز کو باقاعدگی سے گھمائیں اور اگر آپ کو شبہ ہے کہ اس کے ظاہر ہونے پر فوری طور پر کلید کو منسوخ کریں۔ حالیہ پھانسیوں اور ان کے حالات دیکھنے کے لیے ڈیش بورڈ میں مہم چلائیں۔ ایک عملدرآمد `pending`، `queued`، `processing`، `sent`، `skipped`، `cancelled`، `cancelled`، `queued`، `delivery_unknown`.

`skipped` کا مطلب ہے کہ رابطہ ان سبسکرائب یا باؤنس ہو گیا تھا، لہذا Nudgen ایونٹ کو ریکارڈ کرتا ہے لیکن کوٹہ نہیں بھیجتا یا استعمال نہیں کرتا۔ `delivery_unknown` کا مطلب ہے کہ فراہم کنندہ نے ای میل قبول کر لی ہے لیکن حتمی ترسیل کا نتیجہ غیر یقینی تھا۔ ڈپلیکیٹ بھیجنے سے بچنے کے لیے Nudgen خود بخود اس کی دوبارہ کوشش نہیں کرتا ہے۔

پروگرامیٹک سیٹ اپ، ٹرگرنگ، اور عمل درآمد کے سوالات کے لیے، [Developer API](/ur/agents/api) دیکھیں۔
