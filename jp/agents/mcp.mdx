## 概要

Nudgen はアプリのオリジンにある `/mcp` で MCP サーバーを提供します。Streamable HTTP 経由の MCP `2026-07-28` に対応し、OAuth 2.1 が必要です。ブラウザーでサインインし、必要な権限を承認してください。機能が有効な場合、1 つのワークスペース、または現在と将来参加するすべてのワークスペースへのアクセスを明示的に許可できます。ダッシュボードでの切り替えは MCP の既定値を変更しません。

## 複数のワークスペースを使う

既存の接続は、再接続してアクセス範囲の拡大を承認するまで、元のワークスペースに限定されます。すべてのワークスペースを許可した接続では、新しい参加先が自動的に利用可能になります。メンバー資格を失うと、そのワークスペースでの以後の操作は拒否されます。ロール、契約、利用上限は引き続きワークスペースごとに適用されます。

`list_workspaces` に `page` と `pageSize` を渡すと、ID、名前、slug、ロール、既定値を確認できます。`teams:read` が必要です。ワークスペースのツール呼び出しに `workspaceId` を加えると、その操作だけ別の対象を選べます。省略すると接続の既定値を使います。キャンペーンの確認と送信には、同じワークスペース ID を明示してください。

OAuth の同意時に既定のワークスペースを選びます。**設定 → APIキー → 接続済みMCPアプリ**、または `workspaceId` と `teams:write` 権限を使う `set_default_workspace` で変更できます。変更はその接続を使うすべてのチャットに影響します。単一の呼び出しで対象を指定しても既定値は変わりません。既定の対象が削除されたりアクセスできなくなった場合は、別の ID を明示するか既定値を更新してください。Nudgen が自動的に代替を選ぶことはありません。

```jsonl
{"name":"list_workspaces","arguments":{"page":1,"pageSize":25}}
{"name":"list_campaigns","arguments":{"workspaceId":"workspace_b"}}
{"name":"set_default_workspace","arguments":{"workspaceId":"workspace_b"}}
```

既存のリソース URI は既定のワークスペースを使います。以下のテンプレートでは対象を明示できます：

```text
nudgen://workspaces/{workspaceId}/brand
nudgen://workspaces/{workspaceId}/campaigns/{id}/summary
```

## これが重要な理由

アシスタントは連絡先の確認、企業の検索、キャンペーンの下書き作成ができます。チャットで送信や予約を許可すると、ブラウザーの承認リンクなしで直接実行します。

## クライアントを接続する

本番環境のエンドポイントは次のとおりです。

```text
https://app.nudgen.net/mcp
```

OAuth 対応クライアントに **リモート HTTP MCP サーバー**として追加します。クライアントはエンドポイントから Nudgen の認可サーバーを検出し、ブラウザーでのサインインと同意フローを開きます。クライアントにアクセスを許可するワークスペースを選択し、必要なスコープだけを承認してください。

ディスカバリー ドキュメント：

| ドキュメント | URL |
| --- | --- |
| 保護対象リソースのメタデータ | `https://app.nudgen.net/.well-known/oauth-protected-resource/mcp` |
| 認可サーバー | `https://app.nudgen.net/mcp-oauth` |
| サーバー カード | `https://app.nudgen.net/.well-known/mcp/server-card.json` |

認可サーバーは、PKCE S256、リソース バインディング、リフレッシュ トークンのローテーションを伴う認可コード フローを使用します。Client ID Metadata Documents と動的クライアント登録に対応しています。

Codex CLI では、次のコマンドを使用します。

```bash
codex mcp add nudgen --url "https://app.nudgen.net/mcp" --oauth-resource "https://app.nudgen.net/mcp"
codex mcp login nudgen --scopes campaigns:read,campaigns:write,campaigns:send,teams:read,teams:write
```

`nudgen` という名前のクライアントがすでに設定されている場合は、そのエントリを `/mcp` URL で更新してください。

| スコープ | 許可される操作 |
| --- | --- |
| `campaigns:read` | ワークスペース、連絡先、キャンペーン、ブランド設定を確認し、マップリードを検索します。 |
| `campaigns:write` | 連絡先とキャンペーン下書きの作成、ブランド設定の更新、AI 下書きの生成、マップリードのインポートを行います。 |
| `campaigns:send` | キャンペーンの下書きを開始する. |

閲覧には `campaigns:read`、下書きと編集には `campaigns:write`、許可済みの送信操作には `campaigns:send` を使用します。接続時のOAuth同意は引き続き必要です。

<Note>
  パーソナル アクセス トークンは[開発者 API](/jp/agents/api) の認証に使用できますが、`/mcp` の認証には使用できません。MCP クライアントは OAuth サインインを完了する必要があります。
</Note>

## 利用できるツール

| タスク | ツール | スコープ |
| --- | --- | --- |
| ワークスペースを確認する | `get_current_user`, `list_contacts`, `list_campaigns`, `get_campaign`, `get_campaign_stats`, `get_brand_settings` | `campaigns:read` |
| 近隣ビジネスを検索する | `search_map_leads`, `retry_map_leads_enrichment` | `campaigns:read` |
| 作成と編集 | `create_contact`, `create_campaign`, `update_brand_settings`, `generate_email_draft`, `import_map_leads` | `campaigns:write` |
| キャンペーンの下書きを開始する | `launch_campaign`, `send_test_email`, `activate_lifetime_campaign`, `trigger_lifetime_campaign` | `campaigns:send` |

`create_campaign` は、**キャンペーンの下書き（`one-time`、`drip`、`lifetime`）**を保存します。直接送信または予約することはできません。`get_campaign` を使うと、開始前に件名、内容、リンク、オーディエンス、送信者を確認できます。

サーバーは、`campaigns:read` で次の読み取り専用リソースも公開します。

| リソース | 内容 |
| --- | --- |
| `nudgen://api-catalog` | ホストされているツールの名前と説明。 |
| `nudgen://team/brand` | 接続先ワークスペースのブランド設定。 |
| `nudgen://campaigns/{id}/summary` | 1 件のキャンペーンの配信統計。`{id}` をキャンペーン ID に置き換えます。 |

### マップリードを検索してインポートする

1. 都市名と `marketing agency` など、場所とビジネス キーワードを指定して `search_map_leads` を呼び出すようアシスタントに依頼します。
2. 任意のフィルターとして、`radiusKm`（1～100）、`lat` と `lng`、メールアドレスを公開しているビジネスだけを残す `emailOnly` を使用できます。
3. 結果に `nextPageToken` が含まれる場合は、それを `pageToken` として渡して次のページを読み込みます。
4. 同じ場所とキーワードに加えて、保存するリード オブジェクトを指定し、`import_map_leads` を呼び出すようアシスタントに依頼します。1 回の呼び出しで最大 200 件のリードを受け付けます。

インポートすると、接続先ワークスペースに連絡先が書き込まれます。メールアドレスのないリードはスキップされます。既存のリードは更新されます。

### キャンペーンの下書きを開始する

1. `get_campaign` でキャンペーン名、件名、内容、実際の送信者、推定受信者数、送信時刻を確認します。
2. チャットで操作を許可します。アシスタントはキャンペーンIDと、即時送信用の `sendNow: true` またはタイムゾーン付きの将来の日時を指定する `scheduledAt`を指定して `launch_campaign` を直接呼び出します。矛盾する日時指定は使用できません。既に許可した操作を再確認する必要はありません。
3. 返された状態、予約時刻、ダッシュボードへのリンクを確認します。待機中や予約済みは配信済みを意味しません。結果が不明な場合は再試行する前に `get_campaign` と `get_campaign_stats` を確認します。

Nudgenはワークスペースの権限、送信者の準備状態、有効な受信者、契約、上限、キャンペーンのバージョン、キューを引き続き確認します。作成と編集では下書きのみを保存し、配信にはキャンペーンワーカーが必要です。

## アクセスを管理する

**設定 → APIキー → 接続済みMCPアプリ** でアクセスを確認し、既定値を変更したり接続を解除したりできます。複数ワークスペースの接続を解除すると、その接続のトークンと未交換の認可コードがすべてのワークスペースで無効になります。別の REST 接続には影響しません。REST OAuth とアプリ内アシスタントは既存のワークスペース境界を維持します。

## トラブルシューティング

| 症状 | 対処方法 |
| --- | --- |
| サインインが始まらない | クライアントが OAuth 対応のリモート Streamable HTTP MCP をサポートし、`https://app.nudgen.net/mcp` を使用していることを確認します。 |
| ツールに追加の権限が必要 | 再接続し、そのワークスペースに必要なスコープを承認します。 |
| 連絡先検索で条件を絞るよう求められる | 検索は名前とメールアドレスに一致し、タグとステータスのフィルター適用後に最大 5,000 件の連絡先を調べます。フィルターを絞り込んでください。 |
| マップリードのインポートでビジネスがスキップされる | メールアドレスのあるリードだけが保存されます。`emailOnly` を true にして再検索するか、すでにメールアドレスが含まれるリードを選択します。 |
| 古い承認リンクやツール | ツール一覧を更新し、チャットで直接操作を許可してください。古いリンクではキャンペーンを開始できません。 |
| 開始がブロックされる | キャンペーンが下書きであること、送信者の準備状態、対象連絡先、プランのクォータ、[カスタム ドメイン](/jp/settings/sending-domains)を確認します。 |

Bearer トークンと直接 REST エンドポイントを使用するスクリプトについては、[開発者 API](/jp/agents/api) を参照してください。

### 検索範囲と情報補完

APIとMCPは既定で5 kmを使用し、整数の `radiusKm` 1～100を受け付けます。ダッシュボードの確認画面は表示しません。`nextPageToken` を `pageToken` に渡す際は同じ検索条件を維持してください。空のページにも次のページがある場合があります。

`enrichmentPending` は未完了のWebサイト調査を示します。利用可能な `businessSummary` と `businessSources` を確認してください。インポートした情報はキャンペーンの導入文の個別化に役立ちます。メールがない場合、調査が続いている可能性があります。

`enrichmentRetryToken` がある場合、`campaigns:read` 権限で `retry_map_leads_enrichment` に `token` を渡します。トークンは接続したワークスペース専用で、有効期間15分、1回限りです。インポート前に `placeId` で結果を統合してください。`emailOnly` は現在の応答を絞り込むため、再試行後にリードが増える場合があります。

## 下書きの編集と対応範囲

既存の下書きは `update_campaign` で編集し、`delete_campaign` で削除できます。どちらも `campaigns:write` が必要で、メールの送信や予約は行いません。新しい製品機能には専用の OAuth 権限が必要です。要求された場合は再接続して権限を承認してください。

ツール一覧で利用可能なツールと引数を確認できます。ブラウザーへの案内だけでは操作は実行されません。支払い、プロバイダーの認可、招待、ワークスペースの作成・削除・参加、機密性の高い支払い先設定はブラウザーで行います。MCP の対象や既定値を変更してもダッシュボードは切り替わりません。管理機能、認証情報、Webhook、追跡コールバック、内部アシスタントは対象外です。

`get_api_capabilities` でAPIの対応範囲を確認できます。チャットで許可した後、`send_test_email`、`activate_lifetime_campaign`、`trigger_lifetime_campaign` を直接呼び出します。テストはアカウントのメールアドレスにのみ送信します。lifetimeの有効化は今後の自動送信を許可します。ブラウザー承認や承認IDは不要です。結果が不明な場合は再試行の前に状態や実行履歴を確認してください。
